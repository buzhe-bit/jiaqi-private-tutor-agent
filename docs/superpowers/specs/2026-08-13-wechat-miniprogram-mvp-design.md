# 哲学学习私教：微信小程序 MVP 设计

日期：2026-08-13

## 1. 目标

把当前已经跑通的哲学学习私教 H5 做成可导入微信开发者工具的原生小程序。本阶段先完成无正式 AppID 的本地版本；佳琦注册小程序后，只补 AppID、关联 CloudBase 环境并完成真机联调，不重写业务逻辑。

核心学习闭环保持不变：

```text
推荐题目 → 初次作答 → AI 诊断与教学 → 学生复述 → 改进答案
        → 表达笔记 → 个人掌握状态 → 后续复习题
```

## 2. 第 0 步复用审查

结论：选择“基于现有项目改造”，新增一个微信原生小程序前端，继续复用当前 Node + CloudBase 后端。

| 候选 | 维护与许可 | 优点 | 不采用原因 |
| --- | --- | --- | --- |
| 微信原生小程序 | 微信官方示例，MIT | 无构建框架；最贴近平台；依赖和包体最小 | 采用 |
| Taro | 持续维护，MIT | React/Vue 跨端 | 当前只做微信，引入编译链和运行时没有收益 |
| uni-app | 持续维护，Apache-2.0 等 | 多端覆盖最广 | 需要额外工具链，现有原生 JS 迁移成本反而更高 |
| CloudBase Agent UI | 腾讯云官方开源组件 | 通用 AI 聊天快速 | 产品不是通用聊天；会削弱四阶段教学状态与表达笔记结构 |

直接复用：

- 当前全部 API：`health / learner/sync / practice/next / session/start / session/step / session/complete`。
- CloudBase 中的会话、题库和个人掌握档案。
- DeepSeek 服务端调用、提示词、诊断契约、重试和学习状态机。
- 当前“今日训练、答题历史、我的档案、四阶段训练”的信息结构。
- 梅花视觉、三类帮助动作、浮动私教和表达笔记。

不复用：

- 浏览器 DOM 渲染和 `localStorage` 实现。
- H5 顶部/左侧导航布局。
- 通用聊天组件或跨端 UI 框架。

## 3. 本地版本范围

### 3.1 页面

小程序采用底部三栏和一个训练页：

1. `今日训练`：推荐当前题、恢复未完成训练、完成后继续下一题。
2. `训练`：题目常驻、四步进度、学习型对话、三个帮助入口、复述与改写、浮动私教。
3. `答题历史`：按日期查看表达笔记。
4. `我的`：已完成、待复习、需要再练和最近卡点。

训练页作为普通页面进入，不占底部导航，结束后可回到题单或继续下一题。

### 3.2 运行模式

- `local-demo`：没有 AppID 时使用。调用本地确定性适配器，完整跑通界面和状态，不伪称正在使用 DeepSeek。
- `cloudbase`：补 AppID 后使用 `wx.cloud.callContainer` 访问现有 `philosophy-coach` 服务，DeepSeek 密钥只存在服务端。
- 页面显著显示当前是“本地演示”还是“真实私教”，避免再次混淆固定样例与真实 AI。

`project.config.json` 使用微信开发者工具允许的测试 AppID 占位；正式 AppID 通过本地私有配置补充，不提交密钥。

## 4. 最小代码结构

```text
miniprogram/
  app.js / app.json / app.wxss
  config.js
  services/api.js
  services/demo-adapter.js
  utils/storage.js
  utils/format.js
  pages/today/
  pages/training/
  pages/history/
  pages/profile/
  assets/
project.config.json
```

不引入 npm 运行时依赖。页面只维护展示状态，教学判断全部留在服务端；本地演示适配器只覆盖开发预览所需的响应契约。

## 5. 身份与数据

- 本地演示默认使用 `demo` 学员，不写入线上数据库。
- 真机试用第一版继续使用每人独立邀请码，保存到小程序本地缓存。
- 后续有正式 AppID 后再评估是否把邀请码绑定微信身份；本轮不提前建设账号系统。
- 网络失败时保留学生当前草稿和最后一次请求，显示“不是你答错了”，支持原地重试。

## 6. 交互约束

- 每次提交后，当前输入位置立即出现保存和加载状态，不跳回页面顶部。
- 顶部四步进度和逐步展开的梅花同时保留，但梅花不作为唯一进度提示。
- 主回答与浮动私教明确区分：主回答推进训练；浮动私教只追问知识问题，不提交答案、不改变阶段。
- 完成页突出四项：答题抓手、答题思路、我的最终表达、一种可行作答；系统内部卡点不堆到学生页面。
- 所有长文本按结论、解释、知识连接和可写表达分段，避免整块输出。

## 7. 错误与边界

- `callContainer` 超时、非 2xx 或返回契约异常时统一转换成学生可理解的错误。
- 小程序不会保存或接触 DeepSeek API Key。
- 暂不开发语音、OCR、教材上传、RAG、支付、消息推送和复杂登录。
- 不修改现有 CloudBase 集合、飞书表结构和线上部署。

## 8. 代表性行为验收

本地版本至少验证以下 10 条，而不是只看覆盖率：

1. 首次进入能看到今日推荐题并开始训练。
2. 回答“我不知道”后进入帮助选择，不继续催答。
3. 初答提交后进度更新，草稿不丢，页面不跳到顶部。
4. 提示、讲明白和一种可行作答三个入口均可用。
5. 浮动私教追问后仍停留原阶段，主答案草稿完整保留。
6. 复述通过后能进入改进答案，而非无限重复复述。
7. 完成后能复制最终表达，并可直接继续下一题。
8. 答题历史能打开已完成表达笔记。
9. “我的”能展示本地演示档案；真实模式下使用云端同步结果。
10. 服务失败时保留问题、答案和当前阶段，允许原地重试。

页面同时检查约 `390×844` 和 `700×570`：无横向溢出、输入和主按钮不被遮挡、长内容可阅读、进度始终可见。

## 9. 完成标准与退出条件

本地阶段完成标准：项目可被微信开发者工具导入，在测试 AppID 下完整跑通上述四个页面和十条行为样例；自动化测试通过；没有声称本地固定适配器是 DeepSeek。

进入真机阶段的条件：佳琦取得小程序 AppID，并将小程序与现有 CloudBase 环境完成关联。该操作涉及外部账号和平台配置，届时单独确认后执行。
