# 通用哲学学习私教：长期学习闭环设计

日期：2026-08-11

## 1. 产品目标

产品定位为“以哲学史为第一门学科的 AI 学习私教”，帮助学生在考试前把看过的内容转化为能够理解、串联、表达和延迟回忆的知识。

本阶段不适配单一院校口径。首批 3—4 人、理想扩展到 10 人，学生无需上传教材即可开始。三道题是每日推荐基础量，不是上限；完成后可以继续训练。

真正需要验证的最小闭环是：

```text
初答 → 结构化卡点 → 教学干预 → 改进表达 → 掌握状态 → 延迟复习 → 再次作答结果
```

## 2. 范围边界

### 本阶段实现

- 将当前单题诊断结构化保存。
- 累计每名学生对主题、概念和知识关系的掌握状态。
- 从旧卡点生成或选择复习题。
- 以带约束的加权随机方式持续提供新题、关系题和复习题。
- 保留学生最终表达和一种可行作答。
- 记录轻量资料依据状态。
- 以 10 条代表性行为样例作为主要验收依据。

### 本阶段不实现

- 院校专属知识库和答题规范。
- 强制上传参考资料。
- 完整个人 RAG。
- 庞大人工哲学知识图谱。
- 日历、完整知识地图和复杂题库后台。
- 语音、OCR 和原生安装包。
- 为未来通用学科平台提前重构前端。

## 3. 复用审查

选择“基于现有项目改造”，不创建新应用、不安装新依赖。

直接复用：

- 当前四阶段训练状态机：初答、教学、复述、改写。
- `/api/session/start`、`/api/session/step` 和会话签名机制。
- CloudBase `coach_sessions` 主记录和飞书镜像。
- 当前真实 AI 调用、重试和学生草稿保护。
- 当前题目 `guide` 中的问题意识、概念关系、答题结构和可行作答。
- 答题历史、跨设备恢复和完成页表达笔记。
- 佳琦的哲学问题链和一次只处理一个卡点的教学原则。

不直接复用：

- 当前四类 `learnerNeed` 作为长期档案分类。它太粗，只保留为兼容字段。
- 当前“改写超过约 20 字且不同于初答即可闭环”的强制放行规则。
- 当前固定三题目录作为每日训练计划。
- 当前仅检查 `gate` 的旧行为样例作为下一阶段完整验收。

## 4. 总体架构

保留现有 `coach_sessions`，新增两个 CloudBase 集合：

```text
coach_sessions    原始训练证据和完整会话
learner_mastery   学生在主题、概念或知识关系上的累计掌握状态
question_bank     真题、缓存题和 AI 卡点变式题
```

不新增图数据库、消息队列或第三方调度依赖。下一题由一个纯函数式调度模块计算，不单独建立每日队列表。

现有 `coach_sessions` 只增加四个内部字段，不拆表：

- `diagnosis`：本轮结构化诊断。
- `masteryKey`：本轮影响的掌握节点。
- `masterySyncStatus`：`pending / complete`。
- `reviewContext`：当前题是否由旧卡点生成，以及关联的原掌握节点和原会话。

首批 3—10 人继续使用每人一条独立邀请码作为稳定身份；邀请码被多人共用会造成档案混合，因此发放时必须一人一链。当前飞书表继续保存每次会话的教师侧镜像，本阶段不修改飞书表结构。

## 5. 结构化诊断

### 5.1 卡点分类

内部只使用以下六类：

- `knowledge_missing`：知识缺失。
- `concept_misunderstanding`：概念误解。
- `relation_broken`：关系断裂。
- `expression_scattered`：表达散乱。
- `basically_mastered`：基本掌握。
- `delayed_recall_unstable`：延迟复习后仍不稳定。

学生页面继续使用自然语言，不直接展示内部枚举。

### 5.2 模型诊断返回

在现有反馈契约上新增内部 `diagnosis`：

```json
{
  "subject": "哲学",
  "topic": "康德的自由问题",
  "thinker": "康德",
  "concepts": ["理论理性", "实践理性", "自由"],
  "knowledgeRelations": ["理论理性为自由留下可能，实践理性赋予自由实践意义"],
  "issueType": "relation_broken",
  "misconception": "",
  "expressionIssue": "两个层次并列，没有形成论证连接",
  "evidence": "学生答案中能够支持该判断的原句或简短概括",
  "diagnosis": "当前缺少可能性与实践必要性之间的连接",
  "masteryStatus": "unstable",
  "sourceStatus": "ai_synthesized",
  "sourceLabel": "AI 综合现有题目知识边界作出的解释",
  "confidence": "medium"
}
```

`confidence` 只使用 `high / medium / low`。低置信度诊断仍保存证据，但不得自动生成“已经掌握”的结论。

### 5.3 完成条件

移除字数放行。只有同时满足以下条件才完成本轮：

- 学生完成了自己的改写；
- 模型能够指出改写中真实出现的关键关系或表达改善；
- 没有未纠正的核心概念错误；
- 诊断结构完整且与学生证据对应。

服务失败时不更新掌握状态，学生答案和会话仍保留。

## 6. `learner_mastery` 数据模型

一个文档对应“一个学生 × 一个知识节点”。知识节点可以是主题、概念或关系，不要求建设完整知识图谱。

```json
{
  "masteryId": "P01:philosophy:kant-freedom-relation",
  "participantCode": "P01",
  "subject": "philosophy",
  "topic": "康德的自由问题",
  "thinker": "康德",
  "concepts": ["理论理性", "实践理性", "自由"],
  "knowledgeRelation": "理论理性与实践理性通过自由形成体系连接",
  "misconception": "",
  "expressionIssue": "",
  "issueType": "relation_broken",
  "masteryStatus": "developing",
  "delayedRecallResult": "not_tested",
  "reviewAt": "2026-08-14T00:00:00.000Z",
  "attemptCount": 1,
  "firstSeenAt": "2026-08-11T10:00:00.000Z",
  "lastSeenAt": "2026-08-11T10:00:00.000Z",
  "sourceSessionIds": ["session-id"],
  "recentEvents": []
}
```

### 6.1 掌握状态

- `unstable`：当前仍有知识缺失、误解或关系断裂。
- `developing`：本轮已经形成正确表达，尚未经过延迟回忆。
- `stable`：延迟复习中仍能独立表达关键关系。

### 6.2 最近事件

`recentEvents` 最多保存最近 10 次，用来保留有价值的数据链：

```json
{
  "sessionId": "session-20260811-001",
  "questionId": "kant-freedom-keystone",
  "observedAt": "2026-08-11T10:00:00.000Z",
  "initialAnswer": "我知道理论理性和实践理性，但不知道自由怎样连接两者。",
  "issueType": "relation_broken",
  "evidence": "学生已经分别提到两种理性，但没有说明自由如何连接两者。",
  "intervention": "explanation_with_example",
  "improvedExpression": "理论理性为自由留下可能，实践理性使自由成为道德行动的必要预设。",
  "result": "improved",
  "delayedRecallResult": "not_tested"
}
```

完整聊天仍在 `coach_sessions`，掌握档案只保存教学决策需要的证据和结果。

### 6.3 复习时间

第一版采用确定性规则：

- 未掌握、存在误解或延迟复习失败：1 天后。
- 本轮形成正确关系但尚未延迟验证：3 天后。
- 三天后独立回答基本稳定：7 天后。
- 七天后仍稳定：14 天后。

学生当天继续多做题，不改变已经安排好的其他复习任务。

## 7. `question_bank` 数据模型

```json
{
  "questionId": "kant-freedom-keystone",
  "stem": "试从理论理性和实践理性两个层次说明自由为什么是康德体系的拱顶石。",
  "subject": "philosophy",
  "topic": "康德的自由问题",
  "thinker": "康德",
  "concepts": ["理论理性", "实践理性", "自由"],
  "knowledgeRelations": ["理论理性与实践理性的连接"],
  "questionKind": "relation",
  "origin": "past_exam",
  "parentQuestionId": "",
  "guide": {
    "problem": "自然因果与道德责任怎样同时成立",
    "focus": "理论理性留下可能，实践理性赋予实践意义"
  },
  "sourceStatus": "material_supported",
  "sourceLabel": "历年真题",
  "sourceRefs": [],
  "reviewStatus": "reviewed",
  "createdAt": "2026-08-11T10:00:00.000Z",
  "updatedAt": "2026-08-11T10:00:00.000Z"
}
```

题目来源采用已经确认的混合模式：

- 新题和关系题优先从已有真题、缓存题和已生成题中选择。
- 复习题可以根据旧卡点生成变式。
- AI 生成的变式保存到 `question_bank`，下次优先复用，不重复调用模型。
- 生成题保留 `parentQuestionId`，便于追溯原卡点或原题。
- 未经人工抽查的生成题标记 `reviewStatus: unreviewed`，不能显示为权威真题。
- 初始题目不只使用当前三题；从佳琦已有真题语料中导入题干和基础标签，题目知识边界与可行作答由 AI 生成并缓存，人工只抽查明显错误和高风险解释。
- 首轮题量不以固定数字验收，而以试验周期内不会因候选不足被迫立即重复同题为准。

## 8. 下一题调度

新增服务端模块 `practice-selector` 和接口：

```text
POST /api/practice/next
```

输入为当前邀请码和上一题信息，服务端读取：

- 到期的 `learner_mastery`；
- 最近会话和当天已经完成的题；
- `question_bank` 中可用的新题和关系题。

### 8.1 候选池

- 到期复习候选。
- 学生薄弱关系的迁移题候选。
- 尚未覆盖或很少覆盖的新内容候选。

### 8.2 权重

不使用固定三题顺序。基础权重由以下因素组成：

- 已到期且不稳定：最高。
- 旧卡点对应的关系题：较高。
- 未覆盖主题的新题：中等。
- 最近刚做过的相同题目或相同知识关系：大幅降低。
- 加入小幅随机扰动，避免每天顺序机械。

### 8.3 硬约束

- 有到期复习任务时，前三题至少出现一道复习题。
- 同一种题型最多连续两道。
- 同一道题短期内不重复，除非它是明确到期的复习任务。
- 同一知识点已经稳定掌握时，不因随机再次高频出现。
- 没有复习任务时，用关系题或新题补位。

每完成一道题重新计算下一题。三题完成后只提示“今日基础训练完成”，继续提供下一题，不设置每日上限。

## 9. 前端最小改动

- 今日页从固定三题清单改为“当前推荐题＋今日已完成数量”。
- 当前题显示轻量标签：新题、关系题或复习题。
- 完成第三题后显示“今日基础训练完成”，同时保留主按钮“继续下一题”。
- 三题前后都允许暂停，下一次打开恢复未完成会话。
- 完成页继续明确展示“我的最终表达”和“一种可行作答”。
- “我的”页面只增加待复习数量、最近卡点和累计完成题数；本轮不做日历和知识地图。

## 10. 资料依据

内部状态统一为：

- `material_supported`：有已知资料依据，保存 `sourceLabel` 或 `sourceRefs`。
- `ai_synthesized`：AI 基于通行理解和当前题目知识边界综合解释。
- `unverified`：依据不足、存在争议或当前无法确认。

涉及哲学家原句、精确出处、严格文本概念或学术争议时，`unverified` 不得被自动提升为 `material_supported`。学生未上传资料不影响训练启动。

## 11. 失败与数据一致性

- `coach_sessions` 是原始证据源，优先写入。
- 掌握档案更新使用 `sessionId` 保证幂等，重复提交不会累计两次。
- 会话已经完成但掌握档案更新失败时，在会话上记录 `masterySyncStatus: pending`，不阻塞学生完成页。
- 下一次同步或请求下一题时重试 pending 更新。
- AI 题目变式生成失败时，从已有题库降级选择，不显示空白题单。
- 低置信度诊断不会自动把知识点标记为稳定掌握。

## 12. 代表性行为验收样例

验收以行为链为主，不以代码覆盖率或模型措辞相似度为主。

1. **完全不会**：首次回答“不知道”后进入教学；保存 `knowledge_missing`；一天后安排基础复习题。
2. **概念误解**：错误地把实践理性等同于引入上帝；保存具体误解；不得只保存笼统知识缺口。
3. **关系断裂**：概念基本正确但互相并列；保存 `relation_broken`；下一次优先选择同关系的迁移题。
4. **表达散乱**：关键关系已经正确但组织松散；保存 `expression_scattered`；不得重复基础概念教学。
5. **不同但合理**：学生给出不同于参考措辞的合理解释；不得判错或覆盖学生表达。
6. **本轮初步掌握**：改写中出现可指出的真实改善；状态为 `developing`；三天后复习，不能仅凭字数通过。
7. **三天后仍不稳定**：延迟作答再次暴露原卡点；状态回到 `unstable`；`delayed_recall_unstable`；一天后再复习。
8. **七天后稳定**：独立回答仍能说清关键关系；状态升为 `stable`；十四天后再检查。
9. **自由序列调度**：有到期复习时前三题至少包含一道复习题；其余题在新题和关系题中带约束随机；三题后仍可继续。
10. **依据或服务失败**：资料冲突、AI 超时或掌握档案写入失败时，不编造依据、不丢答案、不错误更新掌握状态，并能降级或重试。

每条样例都验证：输入、诊断结构、数据库变化、下一次调度和学生可见结果。现有 11 条旧样例保留为单轮教学回归；新的 10 条样例负责长期学习闭环。

真实模型另外抽取至少 5 条代表性样例做灰度语义检查，不对具体措辞做脆弱断言。

## 13. 验收标准

- 10 条长期行为样例全部通过。
- 当前单题训练回归测试全部通过。
- 学生完成一题后能够在 `learner_mastery` 看到可读的卡点、证据、状态和复习时间。
- 三天或七天延迟复习能够关联原卡点并更新同一掌握档案。
- 下一题同时考虑到期复习、薄弱关系、新内容和当天去重。
- 三题后可以继续训练，页面不宣称当天结束。
- 完成页保留学生最终表达，服务失败不丢草稿。
- 本地在约 `390×844` 与 `700×570` 验证，不直接部署线上。

## 14. 实施阶段

1. 建立代码检查点，保护当前未提交 MVP 改动。
2. 先写 10 条行为验收样例及确定性测试夹具。
3. 扩展诊断契约并移除字数强制放行。
4. 实现 `learner_mastery` 存储和幂等更新。
5. 将当前三题迁入 `question_bank` 作为种子。
6. 实现带约束加权选择器和 `/api/practice/next`。
7. 接入前端“当前推荐题、今日完成数、继续下一题”。
8. 增加轻量资料依据和失败补偿。
9. 跑行为样例、回归测试和两种视口的真实流程。

本阶段不以“拥有多少题”为完成标准，而以“旧卡点能否被再次准确检查并改变后续训练”为完成标准。
