# 哲学私教 MVP：结构化反馈与表达笔记设计

## 目标

把当前单题陪练从“对话结束”推进到“留下能复习、能复制、能再次写出的个人表达笔记”。

学生完成一次训练后，应同时得到：

1. 自己最初和最终的表达；
2. AI 明确补充的知识或论证关系；
3. 一份相对完整的“一种可行作答”；
4. 下一次无提示复习的问题。

本轮仍只服务当前康德固定题，不扩展题库、账号体系、长期掌握度后台或完整知识库。

## 当前问题

1. AI 反馈主要由几个长字符串组成，虽然前端保留换行，但模型经常生成单块长文，重点、证据、缺口和下一步挤在一起。
2. 学生不知道自己已经说对什么、还缺哪一个关键关系、达到什么条件才能进入下一步。
3. 训练结束只有初答与改写对照，没有形成可直接带走的学习产物。
4. CloudBase 模型接口返回非 2xx 时，当前实现直接报错，没有执行自动重试，也没有保留可用于定位的上游状态信息。

## 设计原则

- 一次只处理一个首要问题。
- 重点前置，先给结论，再给解释。
- 学生表达与 AI 补充必须明确分开，不能把 AI 的话伪装成学生已经掌握的内容。
- “一种可行作答”不称为标准答案、满分答案或唯一口径。
- 完成标准是说清一个关键关系并完成一次真实改写，不追求满分答案。
- 先用固定题知识夹具可靠地产出内容，不增加 RAG、队列、多模型切换或新运行时依赖。

## 学员流程

状态机保持不变：

`首次作答 → 教学 → 关键关系复述 → 表达改进 → 完成`

变化只发生在反馈内容与完成页：

1. 学生提交后，AI 反馈按结构化内容块显示。
2. 学生复述不足时，页面明确展示已说对的部分与本轮唯一待补点。
3. 学生完成改写后，系统自动生成表达笔记，不增加额外问卷或生成按钮。
4. 学生可复制整份笔记，也可单独复制“我的最终表达”和“一种可行作答”。

第一版不提供完成页富文本编辑器。学生应在“表达改进”阶段完成自己的修改；完成页只负责整理与复制。

## AI 反馈结构

模型学生可见返回在现有字段基础上新增两个简短字段：

- `studentEvidence`：引用或概括学生已经说对的内容；没有有效内容时明确写“这部分目前还没有形成”。
- `missingPoint`：本轮唯一需要补上的知识、关系或表达问题。

保留：

- `message`：一句话结论，必须重点前置；
- `focus`：本题当前要抓住的一句话；
- `teaching`：教学正文；
- `nextActions`：下一步可选动作。

前端固定按以下顺序渲染，不依赖模型自行编写 Markdown 标题：

1. 一句话结论；
2. “你已经说对的”；
3. “现在只补这一点”；
4. “给你讲清楚”；
5. 下一步动作。

`teaching` 按空行拆成段落，连续短行可显示为项目符号。前端只渲染纯文本，不允许模型 HTML，避免安全和排版不稳定。

## 表达笔记

表达笔记在进入 `complete` 时自动组装，结构固定：

1. 题目；
2. 一句话答题抓手；
3. 我的最初表达；
4. 我已经说清楚的部分；
5. AI 补充的关键关系；
6. 三步答题结构；
7. 我的最终表达；
8. 一种可行作答；
9. 下次无提示复习题。

本题的答题抓手、三步结构、可行作答与复习题来自现有康德知识夹具。学生内容来自会话快照；AI 补充来自本轮 `missingPoint`、`focus` 与教学摘要。这样避免为生成笔记再调用一次模型，降低故障和成本。

服务器返回一个纯数据 `expressionNote` 对象；前端负责展示并确定性生成纯文本。复制动作使用浏览器剪贴板 API，失败时回退为可选中文本区域，不引入第三方依赖。

完成页提供三个动作：

- 复制整份表达笔记；
- 复制我的最终表达；
- 复制一种可行作答。

## 旧私教模块复用

| 模块 | 本轮处理 |
|---|---|
| 讲—问—调 | 继续作为教学回合核心节奏 |
| 每轮一个最小教学单元 | 直接保留，限制一次只讲一个缺口 |
| 答案骨架 | 改造成表达笔记中的三步答题结构 |
| 对比卡、反例卡 | 保留为后续讲解动作，不强制每轮输出 |
| 最小记忆卡 | 改造成一句答题抓手与下次无提示问题 |
| 理解—记忆—迁移 | 作为未来长期掌握度账本的基础，本轮不建立新表 |
| Growth 压力/能量系统 | 只保留暂停、连续失败后缩小任务，不做自动情绪分级 |
| 泛化场景识别 | 固定考研论述场景中暂不采用 |

旧认知追踪中的 `0.72/0.75/0.85` 数值阈值不复用。当前没有足够标注数据支撑这些精确分数，继续采用可观察动作作为完成证据。

## 上游错误恢复

CloudBase 模型请求采用最小重试方案：

1. 非 2xx、超时或网络错误自动重试一次；
2. 重试前使用短暂固定退避，不建立任务队列；
3. 第二次仍失败才向学生返回可重试错误；
4. 学生输入、会话阶段和最后请求继续保存在本机；
5. 服务端日志只记录错误代码、HTTP 状态、上游请求 ID、动作和尝试次数，不记录学生答案、邀请码或密钥。

模型输出格式错误继续使用现有一次重试。所有上游调用总尝试次数最多为两次，避免多层重试叠加。

## 数据与飞书

本轮不创建或修改飞书字段。

- 初答、复述、最终表达继续写入现有字段；
- AI 补充与干预继续进入现有干预字段；
- 表达笔记由已保存的会话数据和固定题夹具确定性生成；
- 完成判断仍写入现有闭环字段。

当前 H5 没有学生账号和历史笔记列表，所以完成页是本轮笔记的主要出口。学生复制到自己的 Obsidian、飞书文档或 Word 中保存。长期表达笔记库和掌握度账本留待验证连续使用价值后再设计。

## 验收标准

### 内容与流程

- 学生每次提交后都能看到“已经说对 / 只缺一点 / 下一步”。
- AI 长讲解至少按语义空行显示为独立段落，不再整块拥挤。
- P04 当前样例应明确显示：理论理性部分已基本正确；实践理性的积极规定与体系连接仍待补。
- 学生完成改写后自动看到完整表达笔记。
- 三种复制动作均得到不含界面标签噪音的纯文本。

### 可靠性

- 首次上游非 2xx 后自动重试，第二次成功时学生不看到错误卡。
- 两次均失败时保留原输入并显示原地重试。
- 日志不包含学生答案或凭据。

### 测试

- 为新增反馈字段、段落拆分、表达笔记组装、复制文本和上游重试补充聚焦测试。
- 保持当前完整测试通过，受影响代码行覆盖率不低于 80%。
- 在约 `700×570` 与 `390×844` 验证长反馈、表达笔记和复制按钮无横向溢出。

## 本轮不做

- 视觉精修、复杂颜色体系或富文本编辑器；
- 多题题库、每日抽题和复习调度；
- 学生账号、历史笔记中心和长期掌握度看板；
- 完整知识库检索或资料自动解析；
- 新飞书表、新字段和自动化工作流；
- 多模型容灾、消息队列或后台任务系统。
