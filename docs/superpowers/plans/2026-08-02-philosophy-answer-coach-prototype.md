# Philosophy Answer Coach Prototype Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a platform-independent Skill that reviews philosophy postgraduate-exam answers for evidence of understanding, selects one high-leverage problem, guides one independent revision, and verifies whether that problem improved.

**Architecture:** Keep the runtime Skill small and route detailed evaluation rules, the Kant pilot fixture, and the experiment protocol into direct references. Use Markdown/JSON assets only; no application, database, model API, or external dependency. Validate the folder structure and non-negotiable behavior with Python standard-library tests plus the official Skill validator.

**Tech Stack:** Markdown, JSON, YAML generated by the official Skill creator scripts, Python 3 standard-library `unittest`.

## Global Constraints

- Skill name is `philosophy-answer-coach`; Chinese display name is `哲学论述陪练`.
- Sources define factual boundaries but never a unique answer template.
- Do not provide a complete model answer before the student's independent attempt.
- Do not default to a total score or claim to represent a professor's unique grading standard.
- Advance by evidence gates, not fixed elapsed time; time is observation data only.
- Select and repair exactly one primary bottleneck per loop.
- When factual support is insufficient or conflicting, mark it `待核实` rather than inventing certainty.
- First pilot uses the Kant freedom question from the approved design.
- Keep the first implementation platform-independent and free of new runtime dependencies.

- [ ] **Step 3: Replace `SKILL.md` with the concise workflow**

The file must contain only the `name` and `description` frontmatter fields, then these exact sections and behavior:

```markdown
# 哲学论述陪练

## 核心立场

把资料当作事实边界，不当作唯一答案。以严格但开放的阅卷人视角判断学生是否扣题、真正理解、建立关系并形成自己的论证。不要声称代表教授的唯一标准。

## 启动输入

取得真题和学生当前独立答案。允许提纲、残缺答案或“不会”的真实说明。学校、年份、分值、资料和自我疑点均为可选输入。

学生独立作答前不得提供完整答案。一次只选择一个首要问题。资料不足时标记为 `待核实`。时间不得作为放行条件。

## 状态路由

1. `CLARIFY_QUESTION`：学生还不能用自己的话说明题目要处理的问题。只给一层审题提示，再让学生重述。
2. `SUBMIT_ATTEMPT`：学生已理解任务但尚未提交当前最好版本。要求提交，不提供答案结构成品。
3. `REPAIR_ONE_ISSUE`：按评价协议找出理解证据和一个首要问题，给一个追问、辨析或小任务。
4. `REWRITE`：学生已通过本轮检查。要求亲自修改对应段落、论证链或提纲。
5. `CLOSE_LOOP`：对照前后版本，只判断本轮问题是否改善，并让学生说清自己改了什么。

每次回复只推进一个状态。连续两次解释仍未通过时缩小任务，不强行进入重写。超过 40 分钟只能建议暂停，不得因耗时而判定通过。

## 资源路由

- 每次阅卷前读取 `references/evaluation-protocol.md`。
- 使用康德自由试验题时读取 `references/kant-freedom-pilot.md`。
- 组织六人试验或记录结果时读取 `references/experiment-guide.md`，并复制 `assets/session-record-template.md`。
```
